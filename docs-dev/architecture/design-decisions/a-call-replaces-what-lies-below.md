# A call replaces what lies below

A dict holding the `call` key discards what a lower layer set at its node during the merge, as a union tag does ([a class tag replaces](class-tag-replaces.md)): `p: {a: 5}` in one file and `p: {call: pkg.square}` in a later one merge to `{call: pkg.square}`, and a lower list does not become the call's `__base__`. The rule is the merge's, by key alone, at every depth, the root included (`_merge._is_call_dict`, asked by `_replaces_what_lies_below` and by `_deep_merge` through `_starts_afresh`). A layer holding only `args` still refines the call below it, and plain data written over a call stays the error it is: `{call: square, a: 3}` holds a key no call takes, and `build()` refuses it.

Why: a call is a finished value. Its spec is the opener and the mapping under `args` ([a computation's arguments nest under args](a-computations-arguments-nest-under-args.md#a-computations-arguments-nest-under-args)), so no key a lower layer left beside it can belong to it: kept, it is either refused by the call or, before `args`, silently taken as an argument (BUG-190). FEAT-28 made `call:` a spec on every typed field and left the merge reading the key as data.

Rejected:

- **Defer to `build()`**, the merge carrying the lower value under a marker for the type-aware default layer to drop under a typed call and merge back otherwise. It loses no data where the type holds `call` as data, but it needs a new marker in what `merge()` returns, a reserved file key so `dump_file(merge())` reads back, and every `${...}` that reads a key under the marker would have to see through it, the cost BUG-220 already shows for deferred list patches.
- **Mark each source by type**, a type-guided walk writing each typed call as a whole-field delete followed by the spec before its layer merges. No new marker, but the type would have to reach file loading, includes and mounts, and the merge is meant to be type-unaware ([merge/build contract](../pipeline/merge-build-contract.md#merge-build-contract)).
- **Replace on nested nodes only**, leaving the root to merge. It would spare a root struct with a member named `call` from losing every lower layer's keys, but break the rule the union tag already follows at the root, for a case as rare there as anywhere.
- **Let plain data over a call replace it.** A patch has nothing to apply to while the value is unknown, but `{a: 3}` is exactly what someone used to the flat grammar writes to refine an argument, so replacing would hide that mistake; the loud refusal stays.

Precedents: confarg's own union tag and cast pin, which the merge also tells by shape and lets replace what lies below. Kubernetes' strategic merge patch spells a replacement by a key in the patch itself (`$patch: replace`). OmegaConf, under Hydra, merges a node holding `_target_` key by key, so switching the target in a later config keeps the old target's arguments, which then fail as unexpected keywords: the pitfall this rule removes.

Cost: where the type holds `call` as data, a `dict` field or a struct with a member named `call`, a higher layer writing that key drops what the lower layers gave the node, at the root as anywhere ([limitations](../limitations.md#callables-and-serialization)). The union tag has the same cost where a struct owns a field of its spelling.
